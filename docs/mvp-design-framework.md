# 通用 MVP 设计框架：三基线 + 一问

> 日期：2026-07-03 | 来源：ChatBI MVP 遗漏权限/租户复盘

## 核心思想

MVP 规划不能只问"做什么功能"，必须同时问"缺了什么就不能交付"。

使用方式：在排任何 Roadmap 之前，先过三张检查表，回答一个问题，再排优先级。

---

## 一、三基线检查表

### 1. 安全基线

> 缺一则不可交付给真实用户。

| 检查项 | 问自己 | 适用场景 |
|--------|--------|---------|
| 身份认证 | 系统知道是谁在操作吗？ | 任何有用户的系统 |
| 数据隔离 | 用户 A 能看到用户 B 的数据吗？ | 多用户/多租户 |
| 接口防护 | 接口可以被无限制调用吗？ | 有 API 暴露 |
| 输入校验 | 用户输入会污染查询/存储吗？ | 有用户输入 |
| 密钥保护 | API Key / 密码会暴露给前端吗？ | 调用外部服务 |

**判断标准**：如果这一列有任何空白，你的 MVP 不能上线给真实用户。

**反模式**："这是内部用的 / 演示用的，先不做"——除非你确定永远不会给外人用，否则这条不成立。

### 2. 功能基线

> 缺一则核心用户链路不通。

| 检查项 | 问自己 | 适用场景 |
|--------|--------|---------|
| 最小闭环 | 用户从输入到拿到结果，链路完整吗？ | 任何项目 |
| 错误降级 | 核心链路断了，用户看到什么？ | 任何项目 |
| 首次体验 | 用户第一次打开，知道怎么用吗？ | 有 UI 的项目 |
| 数据就绪 | 系统跑起来就有数据可看吗？ | 数据产品 |

**判断标准**：找一个非技术人员，从零开始用你的系统。能在不问你任何问题的情况下完成核心任务吗？

### 3. 运维基线

> 缺一则出问题查不到原因。

| 检查项 | 问自己 | 适用场景 |
|--------|--------|---------|
| 请求日志 | 每次请求记录了谁、做了什么、结果如何？ | 有后端 |
| 健康检查 | 怎么知道服务还活着？ | 有后端 |
| 配置管理 | API Key / 数据库连接 / 环境切换怎么管？ | 任何项目 |
| 启动成本 | 一个新同事 clone 下来，几步能跑起来？ | 任何项目 |

**判断标准**：凌晨 3 点接到报警，你能在 5 分钟内定位问题吗？

## 二、一问

> **"如果下周一要把这个系统交给 3 个真实用户使用，还缺什么？"**

使用节点：Phase 规划完成后、开始编码前。

回答方式：列出所有阻止你交付的东西，然后把它们按以下顺序排优先级：

```
安全基线缺失 > 功能基线缺失 > 运维基线缺失 > 功能增强
```

**规则**：
- 安全基线的项，优先级必须高于功能增强
- 不能因为"演示用/内部用"而把安全项推迟——除非你 100% 确定系统永远不会面对多用户
- 如果某条基线确实不适用（如纯前端工具不需要后端日志），明确标注"不适用"而非留空

---

## 三、优先级铁律

```
P0（没有不能上线）    = 安全基线 + 功能基线的最小闭环
P1（核心体验）        = 功能基线的剩余项 + 运维基线
P2（锦上添花）        = 体验增强、高级功能
```

**常见错误**：把高级功能放在安全基线前面。

| 错误示例 | 正确做法 |
|---------|---------|
| 归因分析（P2）进了 MVP，租户隔离（P0）在 TODO | 先做租户隔离，归因分析可以 V0.2 |
| 流式输出（P1）做了，但 API 没鉴权（P0） | 先做鉴权，流式输出可以用普通响应替代 |
| 下钻推荐（P2）做了，但多用户数据混在一起（P0） | 先隔离数据，下钻可以不做 |

---

## 四、使用流程

```
1. 列出所有想做的功能
       │
       ▼
2. 过三基线检查表 → 标记缺失项
       │
       ▼
3. 回答"一问" → 补充遗漏
       │
       ▼
4. 按优先级铁律排序 → P0 / P1 / P2
       │
       ▼
5. P0 全部做完才能叫 MVP
```

## 五、ChatBI 案例对照

用这个框架回头看本项目，当时漏了什么：

| 基线 | 检查项 | 状态 | 说明 |
|------|--------|------|------|
| 安全 | 身份认证 | ❌ | 无 |
| 安全 | 数据隔离 | ❌ | 放在 TODO，没进 MVP |
| 安全 | 接口防护 | ❌ | 无速率限制 |
| 安全 | 输入校验 | ✅ | SQL 参数化 |
| 安全 | 密钥保护 | ✅ | .env + 仅后端使用 |
| 功能 | 最小闭环 | ✅ | NL → SQL → 图表 |
| 功能 | 错误降级 | ✅ | 规则解析兜底 + 友好提示 |
| 功能 | 首次体验 | ✅ | 示例问题引导 |
| 功能 | 数据就绪 | ✅ | generate_data.py 一键造数 |
| 运维 | 请求日志 | ⚠️ | 有技术日志，无用户维度 |
| 运维 | 健康检查 | ✅ | /api/health |
| 运维 | 配置管理 | ✅ | .env |
| 运维 | 启动成本 | ✅ | pip install + npm install |

**核心教训**：不是没能力做权限/租户，而是规划时根本没检查安全基线这一列。
